## Canonical booking model

1. Approved provider publishes docs in **`availability`** (`status: open`).
2. Patient books: one transaction reads open slot, writes **appointments** (`REQUESTED` + `availabilitySlotId`), updates slot to **`booked`**.
3. Rules: appointment create requires `openSlotMatches` (get sees pre-transaction open state); slot update only open→booked with fixed provider/times.

## Guarantee

- Same published slot cannot be booked twice (status transition + transaction).
- Not a guarantee for arbitrary free-text time ranges outside published slots.
